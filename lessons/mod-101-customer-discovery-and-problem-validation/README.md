# mod-101 — Customer Discovery and Problem Validation

**Stage:** IDEA
**Pillar:** GTM
**Hours:** 22 (7 lecture chapters + 6 exercises + 1 lab)
**Track:** [Startup Product & GTM](../../CURRICULUM.md)

> *Interviews that produce information, not compliments.*

## What this module trains

Run the customer-development loop end-to-end — **problem interviews first, then solution interviews, then product interviews** — with Mom-Test discipline (talk about the interviewee's life, ask about the past, ask why), translate the corpus into JTBD outcomes (Ulwick / Christensen), and hand-recruit the first ten interviewees in the "do things that don't scale" tradition. Ship a discovery report on a real (or realistic hypothetical) startup — 20+ interviews summarised into problem statement, top jobs, top forces, disqualifying signals, and three testable hypotheses.

The failure mode the module exists to catch: **the founder builds nine months of product against an assumed problem, an assumed customer, or an assumed solution shape, none of which survives the first honest customer conversation.**

## Learning objectives

- Run the customer-development loop end-to-end — problem interviews first, then solution interviews, then product interviews — and know which failure mode each stage is designed to catch (assumed problem, wrong solution shape, wrong shipping order).
- Apply the Mom Test discipline — talk about the interviewee's life instead of the founder's idea, ask about specifics in the past, ask why they did what they did, and avoid the founder-fishing questions that produce compliments and no information.
- Structure a discovery corpus — one interview note per person, one written synthesis per five interviews, one running theme index — that a co-founder or a first hire can act on without re-interviewing.
- Translate Jobs-to-be-Done outcomes (Ulwick / Christensen) into a testable list of jobs, forces, and outcome statements — and use them to reject solutions that satisfy no important-and-underserved outcome.
- Recognise "do things that don't scale" as an IDEA-stage default — hand-recruiting the first ten customers, running interviews on the phone, following up personally — and know when to stop.
- Ship a discovery report on a real (or realistic hypothetical) startup — 20+ interviews summarised into problem statement, top jobs, top forces, top disqualifying customer signals, and three testable hypotheses for the next round.

## How this module connects to the rest of the track

- **Feeds → [mod-102](../mod-102-pmf-signal-and-measurement)** — the three testable hypotheses in the discovery report become the input to the mod-102 PMF measurement instruments (Sean Ellis survey, retention read).
- **Feeds → [mod-103](../mod-103-positioning-and-messaging)** — the problem statement + top jobs + top forces become inputs to the Dunford five-component positioning frame.
- **Feeds → [mod-104](../mod-104-icp-and-buyer-personas)** — the ICP "who" + disqualifying signals become the seed of the scoreable ICP + disqualification checklist.
- **Feeds → [mod-105](../mod-105-founder-led-sales)** — every discovery-call question in the founder-led-sales script maps to a top job or a top force from this module's report.
- **Feeds → [`project-101-first-thirty-paying-customers`](../../projects/project-101-first-thirty-paying-customers)** — the module's discovery report + the ICP + the disqualifying signals become the applied artifacts for the first thirty paying customers.
